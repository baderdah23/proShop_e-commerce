🌐 لماذا معمارية URL-Driven State؟

  • رابط قابل للمشاركة (Sharable URLs)

    يستطيع العميل نسخ رابط الصفحة ومشاركته مع أي شخص، ليفتح نفس الفلاتر ونفس الترتيب تماماً.

  • تكامل مثالي مع محركات البحث (SEO)

    محركات البحث تستطيع الزحف وفهرسة صفحات الأقسام والماركات بشكل مباشر دون الحاجة لجافاسكريبت ثقيل في الكلاينت.

  • دعم أزرار المتصفح (Back / Forward)

    الرجوع للصفحة السابقة في المتصفح يعيد حالة الفلترة السابقة تلقائياً دون أي كود إضافي.

  • خفة وسرعة الأداء (Zero State Drift)

    بدلاً من إنشاء Context أو Redux ضخم، يكون الـ URL هو المصدر الوحيد للحقيقة (Single Source of Truth).

🛠️ ما هي التقنيات والأدوات المستخدمة؟
الأداة / المكتبة المكان الدور والهدف
useSearchParams & useRouter Frontend Client قراءة وتعديل بارامترات الرابط بسلاسة وبشكل فوري
useTransition (React 19) Frontend Client إبقاء الواجهة مستجيبة أثناء جلب البيانات وعرض سبينر ناعم
use-debounce Frontend Client تأخير البحث النصي 300ms لمنع إرسال طلبات عشوائية مع كل حرف
Zod Backend API التحقق الصارم من صحة ونوع معاملات الـ Query (أرقام، نصوص، قيم Enum)
PostgreSQL GIN / B-Tree Database فهارس مخصصة على الأسعار والتواريخ والبحث بالاسم لتسريع الاستعلام 20x
📝 الملفات التي سنغيرها والملفات التي سننشئها (File Change Impact)

هذا الجدول يوضح بالدقة متناهية كل ملف في الـ Frontend والـ Backend وما الذي سيتم تعديله أو إضافته فيه:

الجهة مسار الملف نوع الإجراء التفاصيل والتغيير المطلوب
Backend backend/src/utils/handlersFactory.ts تعديل إصلاح مشكلة 404 عندما تكون الفلترة فارغة؛ وجعلها تعيد 200 OK مع results: 0, products: [].
Backend backend/src/models/product/product.validation.ts إضافة إضافة ProductQuerySchema للتحقق من معاملات page, limit, sort, brand, category, search, minPrice, maxPrice عبر Zod.
Backend backend/src/models/product/product.routes.ts تعديل إضافة ميدلوير التحقق من الـ Query قبل استدعاء getProducts لضمان أمان السيرفر.
Backend backend/src/models/product/product.repo.ts تحسين أداء فصل حساب total_count باستعلام منفصل خفيف بدلاً من COUNT(*) OVER() الثقيل مع تجميع الصور.
Backend backend/src/db/schema.sql (أو ملف migration) إضافة إضافة فهارس idx_products_price و idx_products_created_at وفهرس pg_trgm للبحث النصي.
Frontend frontend/src/app/products/page.tsx تعديل جوهري قراءة كافة الـ searchParams وتمريرها في استدعاء fetchOrFallback، واستبدال عناصر الـ HTML الثابتة بالمكونات التفاعلية.
Frontend frontend/src/features/products/components/ProductSort.tsx جديد مكون Client تفاعلي للـ Sort Dropdown متصل بالـ URL عبر useSearchParams.
Frontend frontend/src/features/products/components/ProductSearch.tsx جديد مكون Client لشريط البحث النصي يدعم الـ Debounce والتصفير التلقائي لرقم الصفحة.
Frontend frontend/src/features/products/components/ProductFilters.tsx جديد مكون Client للـ Sidebar يحتوي على فلاتر الفئات والماركات مع زر "إعادة ضبط" لتفريغ الفلاتر.
❌ الوضع الحالي (Current State)
  • شريط البحث، دروب داون الترتيب، وفلاتر الفئات في صفحة products/page.tsx هي عناصر HTML ثابتة لا تعمل (غير مربوطة بأي حدث).
  • طلب البيانات يجلب فقط products?limit=18&page=${page} متجاهلاً أي فرز أو تصفية.
  • لو قام مستخدم بطلب بحث عن منتج غير موجود، الباك إند يرمي 404 Not Found مما يربك التطبيق.
  • عدم وجود فهارس لقاعدة البيانات على السعر والتواريخ والبحث بالاسم.
✅ وضع الإنتاج المقترح (Target Production State)
  • كل نقرة فلتر، تغيير ترتيب، أو كتابة بحث تنعكس فوراً في الـ URL بدون وميض في الصفحة (Smooth Transition).
  • السيرفر في Next.js يستقبل الفلاتر ويجلب فقط المنتجات المطلوبة مع معالجة ذكية للنتائج الفارغة.
  • الباك إند يعيد 200 OK مع قائمة فارغة عند عدم وجود نتائج، وتظهر رسالة لطيفة: "لم نجد منتجات مطابقة لخيارات الفلترة".
  • استعلامات PostgreSQL فائقة السرعة بفضل الفهارس المتخصصة وعزل استعلام العدّ السريع.
🚀 مراحل التنفيذ المقترحة (Step-by-Step Roadmap)
تنبيه هندسي: سنقوم بالتنفيذ على مراحل تبدأ من تجهيز الباك إند وقاعدة البيانات أولاً، حتى تكون الـ API جاهزة ومستقرة، ثم بناء مكونات الواجهة في الفرونت إند وربطها بسلاسة.

المرحلة 2: Zod & Route Security

المرحلة 3: Frontend Server Page

تحديث page.tsx لاستقبال كافة معاملات الرابط وتمريرها لمسار جلب المنتجات.

المرحلة 4: Interactive Client Islands

بناء مكونات الترتيب والبحث والفلاتر مع Debounce وإدارة الـ URL بسلاسة تامة.
